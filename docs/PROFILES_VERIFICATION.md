## Требует проверки на автомобиле

1. Реальный Node 8/SDK/Store и сборка manual пакета. ЗдесьNode 24.21.0, arm64 Mac; исполнениеNode 8 недоступно (x64 бинарник без Rosetta не стартовал, Docker daemon отсутствовал). Статический контроль не заменяет целевой запуск.
2. Availability, версии, единицы и значения каждого используемого SOME/IP на G30. MDrive может отсутствовать; DSC/ENGINE и ряд расходных данных пока не имеют подтверждённой расшифровки. Нет диагностических fallback, карты тюнера и управления автомобилем.
3. FES-наддув, BC1/путь, ResetLogic/current consumption, впуск, л/ч/топливо поездки; объём бака и технические пороги. Пока неподтверждённое остаётся прочерком. Метод будущей ограниченной проверки — READ_ONLY_SIGNALS.md.
4. Видимость штатных предупреждений, скорости/селектора и точная видимая область. Полноэкранный фон оригинала потенциально перекрывает штатные слои. Маска X3 и stripClear не доказывают безопасность G30; скрытой корректировки эталона нет.
5. Фактическое освобождение target, возврат штатной приборки, сон/пробуждение, CPU/RSS/GPU и совместная работа с уже установленным renderer. Стендовые drop/reconnect не обещают возврат при любом сбое.

Автомобильная конфигурация остаётся enabled=false и manual. Автозапуск — отдельное действие после ручной проверки запуска, выключения и восстановления штатной приборки. Инструкция — FIRST_CAR_TEST.md. До подтверждения скорости, передачи, штатных предупреждений и отключения дорожные испытания не рекомендованы.

## Исправление остановки локального стенда

Причиной пустого экрана был конфликт двух процессов, пересобиравших одну папку. У каждого экземпляра теперь собственный каталог по порту/PID и собственный SDK stub. Повторные запросы перезапуска объединяются; ошибка сборки показывается явно вне холста без автоматического цикла перезапусков. `node bench/verify-concurrency.js` проверил две одновременные сборки, три серии по десять перезапусков, максимум один дочерний процесс, изоляцию ошибки, ручное исправление и shutdown. Отчёт: `artifacts/bench-concurrency-verification.json`.

Текущий рабочий8078 восстановлен с сохранением введённых значений; имитация сна явно выключена при восстановлении. Проверочные процессы используют отдельные данные и сборки. Проверки сцены ожидают фактический план HUD и его бюджет, а не прежнее фиксированное количество14слоёв.

Последняя правка сохраняет единичную шкалу топлива с прежним показанием в процентах, переносит её на x490 и использует освобождённый x1820 для наддува. Верхний предел его заполнения0–1.6bar сохранён из оригинальной Retro; само численное значение не обрезается по шкале. Проверены нулевой/недоступный/выше максимума boost и работа прежнего warnBoost. При недоступном автомобильном источнике стендовое значение и предупреждение не подставляются.

## Тахометр по200 об/мин и белая основа

Во всех профилях верхняя ось линейная0–8000 об/мин:40 равных ячеек по200. Ширина каждого слота43px при общем размере1720px: тело40px и исходный промежуток3px, скругления Retro2px. Подписи0–8 ×1000 остаются на прежних равномерных координатах.

Заполняются только завершённые блоки:199→0,200→200,399→200,400→400,5999→5800,6000→6000,6999→6800,7000→7000,7999→7800,8000→8000. Доля — floor(clamp(rpm,0,8000)/200)×200/8000. Недоступное значение не заменяется выдуманным; освобождение сцены при критичной потере сохранено. Настройки redline/shift/cold guard не изменены. Цветовые границы фиксированы на6000/8000 и7000/8000. От7000 об/мин все40 ячеек мигают красным с частотой2Гц:250мс ярко,250мс приглушённо (alpha0,18). Ниже7000 обычные зоны и заполнение возвращаются; неизвестный RPM прекращает мигание. Используется существующий tick, дополнительных таймеров нет; архивное мигание сохранено.

`retro_tachometer.js` использует равные слоты span/u_segs и один прежний эффектный слой с прежними uniforms. В рабочем шейдере u_flash=1 означает яркую красную фазу всех ячеек,2 — приглушённую;0 — обычную шкалу. Значение u_value сохраняет фактическое округлённое RPM даже во время вспышки.
