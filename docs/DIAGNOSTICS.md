# Проверка расхода, топлива, наддува и DSC через iDrive

Это средство сбора ограниченного отчёта для ручного выпуска **0.3.2**. Оно не превращает неподтверждённые источники в показания приборки. Сбор и читаемость QR-кодов на этой BMW ещё требуют проверки на месте; локальные тесты не заменяют её. Автозапуск этим выпуском не включается.

## Ручная процедура

1. Автомобиль стоит, селектор P, стояночный тормоз включён. Сначала выполнить проверки штатных предупреждений и выключения приложения из [FIRST_CAR_TEST.md](FIRST_CAR_TEST.md). Не собирать отчёт во время движения.
2. Открыть **Retro Cluster → Проверка данных**. Это страница самого приложения на центральном экране, не отдельный сайт и не команда SSH.
3. Нажать **«Собрать данные · 30 с»** один раз. Дождаться завершения либо выбрать **«Отменить сбор»**. Для сбора не нужно включать полноэкранную отрисовку приборки. Не отключать DSC, не переключать коробку и не вызывать неисправности ради отчёта.
4. После завершения выбрать **«Показать QR-коды»**. Если отчёт разбит на страницы, сфотографировать каждый QR-код с помощью **«Следующий»** / **«Предыдущий»**. Фото можно передать в этот чат. Перед отправкой просмотреть содержание и убрать ненужные сведения.
5. Закрыть страницу после окончания. Отчёт не даёт разрешения на дорожный тест и не требует оставлять приложение опрашивающим автомобиль на ночь.

Приложение ничего не отправляет автоматически, в том числе на GitHub. QR-коды содержат сжатый ограниченный отчёт, а не адрес сервера и не команду установки. Для восстановления нужны **все страницы**: можно передать фотографии либо считанные тексты каждой страницы. Количество страниц зависит от размера отчёта; raw-показания и выбранные определения enum не отбрасываются ради меньшего числа страниц. Если полный отчёт не помещается в ограничения QR, приложение должно показать отказ, а не выдать неполный набор за полный.

Полный ограниченный отчёт также сохраняется в собственном каталоге данных приложения. Запись такого файла не является записью в автомобильные блоки. Не выгружаются VIN, ключи, пароли, географические координаты, полный каталог SOME/IP или SDK. Бенч использует имитацию, которую нельзя принимать за автомобильное наблюдение.

## Восстановление отчёта на Mac

Можно просто передать фотографии всех QR-страниц в чат. Если QR уже считан, сохранить текст каждой страницы в отдельный `qr-1.txt`, `qr-2.txt` и далее в каталоге `diagnostics-private` текущего проекта. Один файл может также содержать JSON-массив всех страниц. Не вставлять вместо считанного текста адрес страницы или пересказ показаний.

Создать каталог для частных файлов:

```sh
mkdir -p diagnostics-private
```

После сохранения текстов собрать отчёт одной командой:

```sh
node tools/read-diagnostics.js diagnostics-private/qr-*.txt --output diagnostics-private/report.json
```

Это полностью локальная операция без подключения к автомобилю. Инструмент проверяет полноту и номера страниц, отсутствие повторов, одинаковую сессию, SHA-256 и ограничение распакованного отчёта 256 KiB. Повреждённый/смешанный/неполный набор отклоняется. Существующий `report.json` не перезаписывается; выбрать новое имя для следующего отчёта. Файл создаётся с правами0600, каталог `diagnostics-private/` исключён из Git. SHA-256 подтверждает целостность передачи, а не правильность расшифровки автомобильных значений.

Команда и проверки CLI покрыты `tests/read-diagnostics.test.js`; локальный тест не означает, что QR уже проверен на экране этой BMW.

## Что нужно выяснить

| Показатель | Основание в исходниках | Что отчёт может подтвердить |
|---|---|---|
| Топливо | `KombiIF.statusRangeTankStatus.fluidLevelFuelTank`; исходный код использует литры | Наличие поля, его raw и состояние источника. Процент требует отдельно подтверждённой ёмкости бака; значение ёмкости не подбирается по этой сессии. |
| Расход | `KombiIF.statusBordcomputerAverage`, `CDS2.statusInjectionVolume`; дополнительные кандидаты `ResetLogic.currentConsumption/averageConsumption` | Фактические члены структур, единицы/enum, доступность и raw. Счётчик впрыска сам по себе не равен л/ч. Масштаб BC ×0.1 в upstream помечен предположительным. |
| Наддув | `FES.statusSwitchDriveDynamicSport2.displayBoostPressure` | Raw и описание типа/единиц, если они реально имеются в каталоге. Upstream ×0.01 bar помечен `q:true`; одно правдоподобное значение не подтверждает масштаб и относительное/абсолютное давление. |
| DSC | `VehicleStabilizationManagement.StabilizationManagement.qualifierFunctionFDR/ASC/ABS` | Реальные типы и enum для каждого qualifier, доступность и raw. До подтверждения семантики это **не** ON/OFF/TRACTION. FES и нажатая кнопка режима не заменяют сигнал DSC. |

Даже название enum может описывать качество/достоверность сигнала или вмешательство системы, а не выбранное состояние стабилизации. Нужны точное определение и сопоставление со штатным отображением. Неизвестное состояние остаётся `—`. Текущие значения не восстанавливаются из прошлого отчёта после сна/перезапуска. Параметры сбора не меняют режим автомобиля, DSC, коробку или двигатель; UDS/OBD/TASU и диагностические сессии здесь не используются.

## Ограниченный экспорт определений

`apps/manuk_retro_cluster/diagnostic_metadata.js` читает только фиксированный локальный файл `/etc/oap/someip/someip-interfaces.json`. Чтение не загружает нативный SOME/IP, SDK или BMW JavaScript и не вызывает getters. Отсутствие файла/прав/подходящей структуры даёт честное `missing`, `unavailable` или `invalid`, без обхода прав. Наличие определения не доказывает, что provider работает и отдаёт пригодные значения.

Разрешены только семь полей пяти интерфейсов:

| Интерфейс | Поля |
|---|---|
| `de.bmw.infotainment.KombiIF` | `statusRangeTankStatus`, `statusBordcomputerAverage` |
| `de.bmw.infotainment.drivingexcitement.FES` | `statusSwitchDriveDynamicSport2` |
| `de.bmw.chassis.VehicleStabilizationManagement` | `StabilizationManagement` |
| `de.bmw.infotainment.vehicle.CDS2` | `statusInjectionVolume` |
| `de.bmw.infotainment.resetlogic.ResetLogic` | `currentConsumption`, `averageConsumption` |

В результате остаются имя интерфейса/поля, наличие getter/notifier, путь члена, `dataRef`, тип и числовые элементы enum. Наследование структур, typedef и массивы учитываются, но массивы не разрешают сбор произвольных живых данных. Произвольные `description`, значения по умолчанию и посторонние свойства не экспортируются. Единицы могут быть отдельным enum-членом; если сведений нет, физическая единица, масштаб и invalid-коды не придумываются.

Для неизвестных структур ResetLogic коллектор получает только безопасные пути числовых/bool/enum-членов из этих определений. Строки, массивы, неразрешённые типы, идентификаторы, координаты и личные поля исключаются. При недоступных определениях нельзя выдать случайный raw JSON за пригодный расход.

Лимиты модуля: входной regular JSON-файл до **8 MiB**, вывод до24 KiB, 2048 шагов обхода, глубина12, до128 членов и до128 элементов одного enum. Размер файла проверяется до выделения буфера, чтения и разбора. Более крупный каталог не загружается: возвращается `limited`, определения остаются недоступными, сбор заранее известных raw-полей может продолжаться. Неизвестные члены ResetLogic без определений не собираются. Это ограничивает объём входа, но не является измеренным пределом памяти приложения: реальный размер каталога и потребление памяти на MGU пока неизвестны.

При превышении границ обхода/вывода частичная таблица удаляется целиком: усечённый enum не используется для расшифровки. В отчёте всегда стоит `evidence: metadata-only`. Прежний предел40 MiB остаётся только у отдельного офлайн-инструмента Mac `tools/find-rpm-limit.js`; он не применяется к чтению каталога внутри автомобильного приложения.

## Как устроены пути установленного приложения

В проверенном Store установленный UID берётся из записи MainApp `data/apps/<id>.json` и сверяется с `source/package.json.name`. В наших исходниках `kit/signals.js::loadConfig` вычисляет `oap_<UID>/someipInterfaces` относительно собственного установленного положения. Поэтому ни старый UID, ни прежний IP не требуются для страницы проверки. Сгенерированные определения нужны для подписок; master-каталог используется только для небольшого экспорта типов. Сохранение enum-имён/единиц в сгенерированном файле заранее не предполагается.

Store имеет `mgu-deploy.sh status --read-only --json`, однако обычный `status` может выполнять обслуживание. Даже `--read-only` собирает общий статус компонентов и может читать provisioning через SOME/IP; для нашей страницы его запуск не нужен. `sdk-donor --json` создаёт копии SDK в `/run`, поэтому **не является** чистым чтением и также не вызывается. Никакой передачи владельцу команд SSH или файлов для размещения эта процедура не требует.
