# Конфигурация

Единственный пользовательский файл — `data/manuk_retro_cluster.json` внутри установки нашего приложения. Код и поставляемые defaults находятся в `source/`; Store сохраняет `data/` при обычном обновлении с тем же id. Удаление приложения удаляет его данные. Стенд хранит независимый файл в `bench/.data/manuk_retro_cluster/`.

Схема версии 7: `config/schema.json`. Валидные версии 1–6 мигрируют атомарно. В v7 удалена настройка `widgets`: приложение показывает только приборку. Независимые `displayUnits` получаются из прежнего `units`; добавляется выключенная опция `startup.onEngineStart`. Более ранние миграции добавляют profiles для v1, удаляют отменённые profiles.slots/profiles.aux и переносят profiles.ecoMaxConsumption в profiles.gaugeMax.consumption. Enabled, ёмкость бака, акценты, followVehicleMode и архивные retro.slots сохраняются. Невалидный файл не исправляется молча. Полные примеры: `config/car.example.json` и `config/bench.example.json`. При первом запуске файл создаётся с правами 0600. Запись идёт во временный файл, `fsync`, затем атомарный `rename`. Повреждённый/невалидный файл не перезаписывается: отрисовка выключается, ошибка сообщается в журнал. Изменения обнаруживаются в течение примерно 500 мс. Снятие флажка **Включить приборку** на странице настроек сначала освобождает слои, затем сохраняет `enabled:false`.

| Поле | Значение и поведение |
|---|---|
| `enabled` | Car: `false`; bench: `true`. Включение разрешает отрисовку только после проверки готовности источников. |
| `language` | `ru` по умолчанию, `en` для исходных английских подписей. Старые файлы без этого поля получают русский язык без сброса остальных настроек. Название приложения Retro Cluster и общепринятые обозначения передач P/R/N сохранены. |
| `layout` | Только `retro80s`. |
| `units` | Сохранённое поле исходной Retro (`metric`/`us`) для архивного режима и совместимости. В рабочей приборке отдельные `displayUnits` имеют приоритет. Одно изменение legacy `units` не заменяет четыре новых выбора. |
| `displayUnits.speed` | `kmh` (по умолчанию) или `mph`; одновременно задаёт км/мили для запаса хода и расстояний. |
| `displayUnits.temperature` | `c` (по умолчанию) или `f`; масло и ОЖ отображаются в °C/°F. |
| `displayUnits.pressure` | `bar` (по умолчанию) или `psi`; наддув в bar/psi, когда достоверный источник доступен. |
| `displayUnits.consumption` | `l100km` (по умолчанию) или `mpg` (US gallon); при доступном отдельном расходе на стоянке — л/ч или gal US/ч соответственно. Не создаёт отсутствующих показаний. |
| `clock` | `24h` или `12h`; сохранён для часов архивной исходной Retro (`profiles.enabled:false`). В рабочих профилях часов нет. |
| `timeZone` | `name: Asia/Yerevan`, `utcOffsetMinutes: 240`. В оригинальную библиотеку передаётся число **240**, не строка. В этой версии поддержан этот фиксированный пояс; нет зависимости от ICU на Node 8. Настройка часов сохранена для архивного эталонного режима. |
| `retro.tankLitres` | Car: `null` — размер бака не подтверждён, процент/полоски топлива недоступны. После подтверждения пользователь может задать ёмкость. `65` в bench — только параметр синтетического эталона. |
| `retro.redline`, `shiftBefore`, `coldGuard`, `shiftCue` | Исходные параметры предупреждений и подсказки переключения; рабочий диапазон тахометра0–8000 не меняет эти настройки. Цветовые зоны рабочего тахометра фиксированы на6000/7000 об/мин и не вычисляются из этих полей; полная красная вспышка рабочего тахометра включается от7000 об/мин независимо от этих полей, на существующем tick. 7000 rpm/300 rpm и алгоритм холодного двигателя унаследованы для сохранения Retro. Это **не подтверждённые технические пределы или рекомендации для конкретного двигателя**. |
| `retro.warnOil`, `warnCoolant`, `warnBoost` | Исходные пороги окраски/мигания, соответственно °C/°C/bar; 0 отключает соответствующее предупреждение. Не заменяют штатные предупреждения BMW. |
| `retro.showBoost` | Сохранённый параметр исходного движка. В оригинальном `retro80s.json` у boost-виджетов нет `toggle`, поэтому этот флаг не скрывает их. В рабочей компоновке наддув постоянно занимает правую вертикальную шкалу; при отсутствии достоверного значения показывается `--`. Исходный JSON сохранён отдельно без изменений. |
| `retro.nightDim` | `off` для точного эталона; `auto` использует исходную приблизительную географию из UTC-смещения. Это не датчик освещения. |
| `retro.stripClear` | Исходная опция: сжимает все слои по высоте 662/720, оставляя нижнюю полосу. Это изменяет геометрию и не гарантирует видимость всех предупреждений. Отдельный пример: `car-parked-strip.example.json`. |
| `retro.slots` | Два исходных правых поля. Допустимы `intake`, `rpm`, `oil`, `coolant`, `boost`, `fuel`, `speed`, `range`. Используются при `profiles.enabled:false`; в новых профилях поля расхода и запаса хода закреплены. |
| `logging.level` | `error`, `warn`, `info`, `debug` для логики приложения. Встроенные lifecycle/SDK ошибки могут записываться независимо. Журнал ограничен 256 KiB с одной ротацией. |
| `startup.mode` | Декларация желаемого режима упаковки (`manually` по умолчанию). **Изменение JSON не включает и не отключает автозапуск в Store.** Авторитетен `package.json.mguAppStartType` устанавливаемого пакета. Автозапуск требует отдельной явной сборки/обновления после ручного теста. |
| `startup.onEngineStart` | `false` по умолчанию. Включённая опция ждёт достоверное прямое `engineRunning:running` внутри уже работающего процесса и активного состояния машины. Подтверждение сохраняется только в памяти текущей эпохи источника и переживает обычный start-stop. Неизвестное состояние, сон, потеря провайдера, перезапуск и `enabled:false` его сбрасывают. **Не запускает остановленный процесс и не меняет install-time `mguAppStartType`.** Подробнее — [AUTOSTART_SETTINGS.md](AUTOSTART_SETTINGS.md). |
| `safety.requireVehicleCondition` | В car обязательно `true`; не разрешается обход через конфигурацию. Неизвестное/отсутствующее состояние не допускает отрисовку. |
| `safety.getterRefreshMs` | 1000 мс: запрос текущих speed/rpm через имеющиеся SOME/IP getter только при доступном источнике, активном состоянии автомобиля и включённой отрисовке. Не диагностика ECU. |
| `safety.criticalReadTimeoutMs` | 3000 мс: ожидание getter. |
| `safety.criticalMaxAgeMs` | 5000 мс: speed/rpm должны подтверждаться уведомлением или успешным getter. Последние два интервала вместе должны быть меньше этого окна. Для событийных режима, передачи, температур и состояний действует период доступности провайдера и жизненный цикл автомобиля. Момент/G имеют окно 3 с; топливо/BC/шины — 35 с при периоде getter 10 с. Потеря единиц инвалидирует шины. Подробнее — DATA_SOURCES.md. |

Впуск на машине пока `--`: первоначальный источник оригинала требовал диагностического опроса. В первой версии его нет. FES boost сохраняется как неподтверждённый raw/candidate: upstream помечает его масштаб q:true, поэтому на автомобильной шкале наддува остаётся `--`, `value=null`. Наличие шкалы не подтверждает источник; синтетическое значение доступно только стенду. Неизвестные значения немедленно заменяют старые, передачи не вычисляются по скорости/оборотам.

Проверенные локальные команды (не подключаются к машине):

```sh
node tools/config.js --file /absolute/path/manuk_retro_cluster.json init
node tools/config.js --file /absolute/path/manuk_retro_cluster.json validate
node tools/config.js --file /absolute/path/manuk_retro_cluster.json enable
node tools/config.js --file /absolute/path/manuk_retro_cluster.json disable
```

`init` отказывается перезаписывать существующий файл. Для стенда: `--profile bench init`. После ручного редактирования запускайте `validate` до переноса файла. На автомобиль передаётся именно car-конфигурация; файл bench с синтетической ёмкостью туда не копируется.

## Три профиля и постоянные показатели

| Поле | Поведение |
|---|---|
| profiles.enabled | true: три профиля с общей светлой основой и отдельными акцентами; false: архивная исходная Retro для сравнения, не отдельный дизайн для движения. |
| profiles.followVehicleMode | true: профиль по отдельномуFES. false: нейтральная палитра, точная подпись источника сохраняется. |
| profiles.accents | Ровноcomfort/sport/eco, #RRGGBB; #FFB21C/#FF3B30/#398BFF по умолчанию. Меняют только название режима; фиксированные цвета RPM от них не зависят. Скорость, боковые шкалы и подписи сохраняют основу Adaptive RGB190/198/204 (`#BEC6CC`). Adaptive/unknown светлые; предупреждения отдельно жёлтые. |
| profiles.gaugeMax.consumption | Максимум только левой вертикальной шкалы текущего расхода, **л/100 км**. По умолчанию 30, допустимо 10–60. |
| profiles.gaugeMax.range | Максимум вертикальной шкалы штатного запаса хода, **км**. По умолчанию 1000, допустимо 100–3000. |
| profiles.gaugeMax.fuelFlow | Максимум вертикальной шкалы расхода на стоянке, **л/ч**, когда достоверный fuelFlow доступен. По умолчанию 10, допустимо 1–100. |

Разделитель в строке режима и DSC ON/неизвестное состояние всегда используют светлую основу. OFF/TRACTION/вмешательство/неисправность в строке состояния жёлтые независимо от акцента. Название режима сохраняет свой цвет; строка остаётся одним виджетом с отдельными цветными масками. Изменения палитры не меняют значения `profiles.accents` или правила источников.

Цветовые зоны тахометра одинаковы во всех профилях: участок 0–<6000 об/мин — светлый `#BEC6CC`, 6000–<7000 — жёлтый `#FFE040`, 7000–8000 — красный `#FF3B30`. Подписи 0–5 светлые, 6 жёлтая, 7 и 8 красные. Это фиксированные визуальные зоны, независимые от `redline`, `shiftBefore` и `coldGuard`; сами настройки сохранены. При достоверном RPM от7000 вся шкала из40 ячеек мигает красным `#FF3B30`: яркая фаза и тусклая красная фаза с alpha0,18 сменяются каждые250мс (полный цикл500мс, 2Гц). Ниже7000 действуют обычные белая/жёлтая/красная зоны и заполнение полными ячейками по200. Исходное RPM и рассчитанное по нему заполнение не подменяются максимальным значением ради вспышки. Используется существующий tick, без дополнительных таймеров. Недоступное RPM отменяет мигание; прежняя политика освобождения отображения при потере критичных данных сохраняется. Архивная исходная Retro и настройки redline/shiftBefore/coldGuard не изменены;7000 — фиксированный визуальный порог, не подтверждённый технический предел двигателя.

Все три значения — только масштабы отрисовки. Они **не являются характеристиками автомобиля, ёмкостью бака, допустимым расходом или аварийными порогами**. Значение показателя не вычисляется из максимума и не ограничивается им: заполнение равно `clamp(значение / максимум, 0, 1)`, а число показывает исходное достоверное показание в выбранных единицах. Недоступное значение остаётся прочерком и не превращается в ноль. Максимумы всегда задаются в перечисленных базовых единицах; менять их вслед за переводом числа в mpg/мили через `displayUnits` не требуется.

Пример части файла:

```json
"gaugeMax": {
  "consumption": 30,
  "range": 1000,
  "fuelFlow": 10
}
```

Этот объект располагается внутри `profiles`. Прежний ключ `ecoMaxConsumption` в схеме 5 больше не допускается. Миграция v4 переносит его точное пользовательское значение; неизвестные, нулевые, отрицательные, бесконечные и выходящие за допустимые диапазоны максимумы отклоняются. Неполная или неоднозначная старая конфигурация не сбрасывается к правдоподобным значениям: файл сохраняется, отрисовка выключается.

Слева закреплены три вертикальные шкалы: текущий расход (центр x200), запас хода (x345) и прежний уровень топлива в процентах (x490). Справа — масло (x1530), ОЖ (x1675) и наддув (x1820); топливо справа не дублируется. Шесть вертикальных шкал имеют по15 сегментов. Верхняя во всех профилях, включая Eco и нейтральный, — тахометр0–8000 об/мин с40 равными ячейками по200 об/мин на линейной оси RPM, подписи0–8 ×1000; расход больше не подменяет его. Это фиксированная геометрия, а не отдельная настройка данных. Наддув сохраняет исходный диапазон 0–1,6 bar; отдельный `gaugeMax` для него не добавлен; текущая схема — 7. Средний расход отменён. profiles.slots и profiles.aux удалены в схемах 3/4 по уточнениям владельца; интерфейс стенда больше не предлагает эти поля. Во всех трёх профилях расположение и содержимое вертикальных шкал одинаковые; температура впуска/путь BC/числовые RPM также не выводятся. Часы и строка двигателя удалены из рабочих профилей; `clock` и `timeZone` остаются для архивного эталонного режима. Источники остальных сигналов и их metadata сохранены для read-only проверки, но наличие обработчика не означает присутствие показателя на экране.

При нулевой скорости л/100км не показываются. Допустимы л/ч только при доступном отдельном fuelFlow; иначе --. Неизвестная скорость также даёт прочерк расхода. Запас хода берётся из штатного сигнала, не из процента топлива. При displayUnits.consumption:mpg расход переводится в mpg US, fuelFlow — в gal US/ч; при displayUnits.speed:mph запас хода переводится в мили. Эти варианты выбираются независимо. Расход отображается только в отдельной левой шкале; `profiles.gaugeMax.consumption` не влияет на верхний тахометр.

Обычное заполнение тахометра использует целые ячейки; от7000 визуально мигают все40 без подмены RPM или рассчитанного заполнения. Для `r = clamp(rpm, 0, 8000)` число `n = floor(r/200)`, `u_value = n/40`. Пороги: 199→0, 200→1, 400→2, 6000→30, 7000→35, 8000→40. При ширине1720px все40 слотов равны43px: видимое тело40px и зазор3px. Подписи0–8 равномерно располагаются через1/8 ширины. Цветовые границы тахометра фиксированы на6000/8000 и7000/8000 ширины; `redline` и shift cue сохранены в конфигурации, но не задают эти зоны. Выше8000 ограничивается только заполнение; при недоступном RPM шкала пуста и действует прежняя защита критичных данных. Берётся свежее нормализованное RPM для точного порога, остальное shared-сглаживание сохранено. Максимум8000 фиксирует диапазон отрисовки, не `redline`, `shiftBefore`, `coldGuard` и не характеристики двигателя. Параметры тахометра не добавляют настроек; текущая схема 7 содержит независимые единицы и ожидание двигателя; виджеты удалены.

forceProfile, ENGINE/DSC/передача и сырые значения не входят в конфигурацию. Стендовые overrides находятся только в исключённом из автомобильного пакета bench. Принудительный профиль меняет только представление и сохраняет точнуюFES подпись. Панель стенда сохраняет акценты/параметры через ту же схему и атомарную запись. Тест освобождения экрана использует отдельный стендовыйsimulateCarSafety.

## Настройки на экране iDrive

При ручном открытии **Retro Cluster** доступны четыре группы: **Включить приборку**, **Включать при запуске двигателя**, **Язык**, **Единицы измерения**. Выбор RU/EN переводит настройки и подписи приборки; единицы скорости, температуры, давления и расхода задаются независимо. Изменения используют тот же `ConfigStore` и атомарное сохранение. Закрытие страницы не выключает фон, снятие флажка отображения освобождает наши слои. Автоматического открытия страницы нет.

Минимальный фрагмент новых параметров:

```json
"startup": { "mode": "manually", "onEngineStart": false },
"displayUnits": {
  "speed": "kmh",
  "temperature": "c",
  "pressure": "bar",
  "consumption": "l100km"
}
```

Это фрагмент полного файла схемы 7, не самостоятельный JSON-конфиг. Центральные виджеты отменены в версии приложения 0.3.0; схема отклоняет `widgets`. Исторические WIDGET-документы оставлены только как исследовательский архив. Ни режим, ни передача, ни DSC, ни engineRunning или подтверждение запуска не сохраняются в пользовательском JSON.
