# Конфигурация

Единственный пользовательский файл — `data/manuk_retro_cluster.json` внутри установки нашего приложения. Код и поставляемые defaults находятся в `source/`; Store сохраняет `data/` при обычном обновлении с тем же id. Удаление приложения удаляет его данные. Стенд хранит независимый файл в `bench/.data/manuk_retro_cluster/`.

Схема версии 7: `config/schema.json`. Валидные версии 1–6 мигрируют атомарно. В v7 удалена настройка `widgets`: приложение показывает только приборку. Независимые `displayUnits` получаются из прежнего `units`; добавляется выключенная опция `startup.onEngineStart`. Более ранние миграции добавляют profiles для v1, удаляют отменённые profiles.slots/profiles.aux и переносят profiles.ecoMaxConsumption в profiles.gaugeMax.consumption. Enabled, ёмкость бака, акценты, followVehicleMode и архивные retro.slots сохраняются. Невалидный файл не исправляется молча. Полные примеры: `config/car.example.json` и `config/bench.example.json`. При первом запуске файл создаётся с правами 0600. Запись идёт во временный файл, `fsync`, затем атомарный `rename`. Повреждённый/невалидный файл не перезаписывается: отрисовка выключается, ошибка сообщается в журнал. Изменения обнаруживаются в течение примерно 500 мс. Снятие флажка **Включить приборку** на странице настроек сначала освобождает слои, затем сохраняет `enabled:false`.

| Поле | Значение и поведение |
|---|---|
| `enabled` | Car: `false`; bench: `true`. Включение разрешает отрисовку только после проверки готовности источников. |
| `language` | `ru` по умолчанию, `en` для исходных английских подписей. Старые файлы без этого поля получают русский язык без сброса остальных настроек. Название приложения Retro Cluster и общепринятые обозначения передач P/R/N сохранены. |
| `layout` | Только `retro80s`. |
| `units` | Сохранённое поле исходной Retro (`metric`/`us`) для архивного режима и совместимости. В рабочей приборке отдельные `displayUnits` имеют приоритет. Одно изменение legacy `units` не заменяет четыре новых выбора. |
| `displayUnits.speed` | `kmh` (по умолчанию) или `mph`; одновременно задаёт км/мили для запаса хода и расстояний. |
| `displayUnits.temperature` | `c` (по умолчанию) или `f`; масло и ОЖ отображаются в °C/°F. |
| `displayUnits.pressure` | `bar` (по умолчанию) или `psi`. Параметр сохранён для доступных показаний давления и архивной Retro; в рабочей компоновке 0.3.4 наддува нет. |
| `displayUnits.consumption` | `l100km` (по умолчанию) или `mpg` (US gallon); при доступном отдельном расходе на стоянке — л/ч или gal US/ч соответственно. Не создаёт отсутствующих показаний. |
| `clock` | `24h` или `12h`; сохранён для часов архивной исходной Retro (`profiles.enabled:false`). В рабочих профилях часов нет. |
| `timeZone` | `name: Asia/Yerevan`, `utcOffsetMinutes: 240`. В оригинальную библиотеку передаётся число **240**, не строка. В этой версии поддержан этот фиксированный пояс; нет зависимости от ICU на Node 8. Настройка часов сохранена для архивного эталонного режима. |
| `retro.tankLitres` | Car: `null` — размер бака не подтверждён, процент/полоски топлива недоступны. После подтверждения пользователь может задать ёмкость. `65` в bench — только параметр синтетического эталона. |
| `retro.redline`, `shiftBefore`, `coldGuard`, `shiftCue` | Исходные параметры предупреждений и подсказки переключения; рабочий диапазон тахометра 0–8000 не меняет эти настройки. Цветовые зоны рабочего тахометра фиксированы на 6000/7000 об/мин и не вычисляются из этих полей; полная красная вспышка рабочего тахометра включается от 7000 об/мин независимо от этих полей, на существующем tick. 7000 rpm/300 rpm и алгоритм холодного двигателя унаследованы для сохранения Retro. Это **не подтверждённые технические пределы или рекомендации для конкретного двигателя**. |
| `retro.warnOil`, `warnCoolant`, `warnBoost` | Исходные пороги окраски/мигания, соответственно °C/°C/bar; 0 отключает соответствующее предупреждение. `warnBoost` сохранён для архивной Retro, в рабочей компоновке наддува нет. Не заменяют штатные предупреждения BMW. |
| `retro.showBoost` | Сохранённый параметр исходного движка. В оригинальном `retro80s.json` у boost-виджетов нет `toggle`, поэтому этот флаг не скрывает их. В рабочей компоновке 0.3.4 наддув удалён независимо от этого флага; включение `showBoost` не возвращает его. Исходный JSON сохранён отдельно без изменений. |
| `retro.nightDim` | `off` для точного эталона; `auto` использует исходную приблизительную географию из UTC-смещения. Это не датчик освещения. |
| `retro.stripClear` | Исходная опция: сжимает все слои по высоте 662/720, оставляя нижнюю полосу. Это изменяет геометрию и не гарантирует видимость всех предупреждений. Отдельный пример: `car-parked-strip.example.json`. |
| `retro.slots` | Два исходных правых поля. Допустимы `intake`, `rpm`, `oil`, `coolant`, `boost`, `fuel`, `speed`, `range`. Используются при `profiles.enabled:false`; в новых профилях поля расхода и запаса хода закреплены. |
| `logging.level` | `error`, `warn`, `info`, `debug` для логики приложения. Встроенные lifecycle/SDK ошибки могут записываться независимо. Журнал ограничен 256 KiB с одной ротацией. |
| `startup.mode` | Декларация желаемого режима упаковки (`manually` по умолчанию). **Изменение JSON не включает и не отключает автозапуск в Store.** Авторитетен `package.json.mguAppStartType` устанавливаемого пакета. Автозапуск требует отдельной явной сборки/обновления после ручного теста. |
| `startup.onEngineStart` | `false` по умолчанию. Включённая опция ждёт достоверное прямое `engineRunning:running` внутри уже работающего процесса и активного состояния машины. Подтверждение сохраняется только в памяти текущей эпохи источника и переживает обычный start-stop. Неизвестное состояние, сон, потеря провайдера, перезапуск и `enabled:false` его сбрасывают. **Не запускает остановленный процесс и не меняет install-time `mguAppStartType`.** Подробнее — [AUTOSTART_SETTINGS.md](AUTOSTART_SETTINGS.md). |
| `safety.requireVehicleCondition` | В car обязательно `true`; не разрешается обход через конфигурацию. Неизвестное/отсутствующее состояние не допускает отрисовку. |
| `safety.getterRefreshMs` | 1000 мс: запрос текущих speed/rpm через имеющиеся SOME/IP getter только при доступном источнике, активном состоянии автомобиля и включённой отрисовке. Не диагностика ECU. |
| `safety.criticalReadTimeoutMs` | 3000 мс: ожидание getter. |
| `safety.criticalMaxAgeMs` | 5000 мс: speed/rpm должны подтверждаться уведомлением или успешным getter. Последние два интервала вместе должны быть меньше этого окна. Для событийных режима, передачи, температур и состояний действует период доступности провайдера и жизненный цикл автомобиля. Момент/G имеют окно 3 с; топливо/BC/шины — 35 с при периоде getter 10 с. Потеря единиц инвалидирует шины. Подробнее — DATA_SOURCES.md. |

Впуск пока не имеет подтверждённого пассивного источника; диагностический опрос исходного приложения не включён. FES boost сохраняется как неподтверждённый `raw/candidate` при `value=null`; удаление его виджета не меняет качество источника. Мгновенный расход и л/ч также не подменяются средним расходом. Подтверждённые владельцем 13,9 л/100 км относятся к среднему BC1, а не к текущему расходу. Источники и пределы подтверждения описаны в [DATA_SOURCES.md](DATA_SOURCES.md). Неизвестные значения заменяют старые, передачи не вычисляются по скорости и оборотам.

Проверенные локальные команды (не подключаются к машине):

```sh
node tools/config.js --file /absolute/path/manuk_retro_cluster.json init
node tools/config.js --file /absolute/path/manuk_retro_cluster.json validate
node tools/config.js --file /absolute/path/manuk_retro_cluster.json enable
node tools/config.js --file /absolute/path/manuk_retro_cluster.json disable
```

`init` отказывается перезаписывать существующий файл. Для стенда: `--profile bench init`. После ручного редактирования запускайте `validate` до переноса файла. На автомобиль передаётся именно car-конфигурация; файл bench с синтетической ёмкостью туда не копируется.

## Три профиля и постоянные показатели

| Поле | Поведение |
|---|---|
| `profiles.enabled` | `true`: одна рабочая приборка с тремя акцентами; `false`: архивная исходная Retro для сравнения. |
| `profiles.followVehicleMode` | `true`: профиль по фактическому FES. `false`: нейтральная палитра; точная подпись источника сохраняется. |
| `profiles.accents` | Ровно `comfort`, `sport`, `eco` в формате `#RRGGBB`; значения по умолчанию `#FFB21C`, `#FF3B30`, `#398BFF`. Меняют только название режима, не цвета тахометра или источники. |
| `profiles.gaugeMax.consumption` | Максимум шкалы текущего расхода в **л/100 км**: по умолчанию 30, допустимо 10–60. |
| `profiles.gaugeMax.range` | Максимум шкалы штатного запаса хода в **км**: по умолчанию 1000, допустимо 100–3000. |
| `profiles.gaugeMax.fuelFlow` | Максимум шкалы расхода на стоянке в **л/ч**, если отдельный достоверный источник доступен: по умолчанию 10, допустимо 1–100. |

Скорость, передача, боковые шкалы и подписи сохраняют светлую основу Adaptive `#BEC6CC`. Только название режима окрашивается акцентом: Comfort — янтарным, Sport/Sport+ — красным, Eco — синим; Adaptive и неизвестный режим светлые. Разделитель и DSC ON/неизвестное состояние светлые. OFF, TRACTION, вмешательство и неисправность — жёлтые независимо от акцента. Строка остаётся одним виджетом, данные FES и DSC не выводятся друг из друга.

Три `gaugeMax` задают только масштабы отрисовки. Они **не являются характеристиками автомобиля, объёмом бака, допустимым расходом или аварийными порогами**. Заполнение равно `clamp(значение / максимум, 0, 1)`, а число показывает достоверное значение в выбранных единицах без ограничения по максимуму шкалы. Недоступное значение остаётся прочерком. Максимумы задаются в базовых единицах независимо от выбранных mpg/миль.

Пример объекта внутри `profiles`:

```json
"gaugeMax": {
  "consumption": 30,
  "range": 1000,
  "fuelFlow": 10
}
```

Прежний `ecoMaxConsumption` не допускается текущей схемой 7. Миграция переносит его точное пользовательское значение; неизвестные, нулевые, отрицательные и выходящие за допустимые диапазоны максимумы отклоняются. Неоднозначная старая конфигурация не сбрасывается к правдоподобным значениям: файл сохраняется, отрисовка выключается.

В версии 0.3.4 слева закреплены текущий расход, запас хода и топливо с центрами **x150, x295, x440**. Справа — только масло и охлаждающая жидкость с центрами **x1631, x1770**. Все пять вертикальных шкал имеют 15 сегментов, размеры 52×262 px и одинаковые координаты во всех профилях. Наддув удалён целиком; `showBoost` и `warnBoost` не возвращают его в рабочий layout. Правые шкалы отнесены за консервативную область штатной передачи; точная проверка на G30 ещё требуется. Геометрия приведена в [LAYOUT_PROFILES.md](LAYOUT_PROFILES.md).

Тахометр, общая группа скорости/передачи и отдельная строка режима/DSC центрированы на **x960** холста 1920×720. Средний расход, впуск, путь BC, отдельное число RPM, часы и строка двигателя в рабочую компоновку не входят. `clock`, `timeZone` и архивные `retro.slots` сохранены для эталонного режима. Наличие обработчика или диагностического показания не означает наличие виджета на экране.

При нулевой скорости л/100 км не показываются. Л/ч допустимы только при доступном отдельном `fuelFlow`; иначе отображается прочерк. Неизвестная скорость также не допускает показания расхода. Запас хода берётся из штатного сигнала, не из процента топлива. При `displayUnits.consumption:mpg` используются mpg US и gal US/ч; при `displayUnits.speed:mph` запас хода переводится в мили. Выборы независимы, исходные значения не изменяются.

## Тахометр и плавность

Во всех профилях верхняя шкала показывает RPM на линейной оси 0–8000: **80 ячеек по 100 об/мин**. При ширине 1720 px слот занимает 21,5 px, видимое тело — 18,5 px, зазор — 3 px. Подписи 0–8 ×1000 расположены через равные доли ширины. Это фиксированная геометрия приложения, отдельной пользовательской настройки числа ячеек нет.

До 6000 об/мин ячейки зелёные `#50FF78`, от 6000 до 7000 — жёлтые `#FFE040`, от 7000 до 8000 — красные `#FF3B30`. Подписи 0–5 светлые, 6 — жёлтая, 7 и 8 — красные. При свежем исходном RPM от 7000 все 80 ячеек мигают красным: яркая и тусклая фазы с alpha 0,18 сменяются каждые 250 мс. Эти визуальные пороги не зависят от `redline`, `shiftBefore`, `coldGuard` и не являются подтверждёнными техническими пределами двигателя.

Заполнение использует `n = floor(clamp(rpm, 0, 8000) / 100)`, `u_value = n / 80`: 99 → 0 ячеек, 100 → 1, 199 → 1, 6000 → 60, 7000 → 70, 8000 → 80. В рабочем режиме отображаемое RPM достигает нового образца с интерполяцией до 100 мс; красное мигание и проверка доступности используют исходное RPM без этой задержки. Вспышка не подменяет само показание значением 8000. Недоступный RPM очищает заполнение и отменяет вспышку, сохраняя существующую защиту критичных источников.

Скорость и RPM обслуживаются одним таймером 34 мс — целевой частотой около 29,4 Гц. Старое ограничение текста скорости в 200 мс снято. Интерполяция относится только к отображению и не меняет реальные данные, getter-периоды или правила свежести. Реальный ноль показывается сразу; потеря данных, новая эпоха источника, сброс сцены и пауза отрисовки сбрасывают переход. При занятом renderer промежуточные кадры пропускаются без очереди. Это не обещание фактических 30 кадров/с на MGU или показа каждого целого числа при любом ускорении. Отдельных настроек частоты и интерполяции в схеме 7 нет.

Синяя полоса холодного ограничения подготовлена только для будущего подтверждённого источника. Сейчас она скрыта: нет достоверного пассивного `coldRpmLimit`. Температура, таймер или конфигурация не заменяют такой сигнал. См. [COLD_RPM_SIGNAL.md](COLD_RPM_SIGNAL.md).

`forceProfile`, ENGINE/DSC, передача и сырые сигналы не входят в автомобильную конфигурацию. Стендовые overrides находятся только в `bench`, исключённом из автомобильного пакета. Принудительный профиль меняет представление, сохраняя точную FES-подпись. Панель стенда сохраняет допустимые настройки через ту же схему и атомарную запись; проверка освобождения экрана использует отдельный стендовый `simulateCarSafety`.

## Настройки на экране iDrive

При ручном открытии **Retro Cluster** доступны четыре группы: **Включить приборку**, **Включать при запуске двигателя**, **Язык**, **Единицы измерения**. Выбор RU/EN переводит настройки и подписи приборки; единицы скорости, температуры, давления и расхода задаются независимо. Изменения используют тот же `ConfigStore` и атомарное сохранение. Закрытие страницы не выключает фон, снятие флажка отображения освобождает наши слои. Автоматического открытия страницы нет.

Минимальный фрагмент новых параметров:

```json
"startup": { "mode": "manually", "onEngineStart": false },
"displayUnits": {
  "speed": "kmh",
  "temperature": "c",
  "pressure": "bar",
  "consumption": "l100km"
}
```

Это фрагмент полного файла схемы 7, не самостоятельный JSON-конфиг. Центральные виджеты отменены в версии приложения 0.3.0; схема отклоняет `widgets`. Исторические WIDGET-документы оставлены только как исследовательский архив. Ни режим, ни передача, ни DSC, ни engineRunning или подтверждение запуска не сохраняются в пользовательском JSON.
