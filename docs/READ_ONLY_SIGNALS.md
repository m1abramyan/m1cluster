# Проверка источников на стоящем автомобиле

Для ручного выпуска 0.3.3 подготовлена [проверка через обычный список iDrive](DIAGNOSTICS.md): **Retro Cluster → Проверка данных → Показать значения** после 30-секундного сбора. Сфотографировать все страницы, перелистывая их вручную. Это основной вариант для владельца, без QR, команд SSH и размещения файлов на MGU. Он собирает только ограниченный набор спорных источников и выбранные определения типов; фотографии передаются вручную. Показания не становятся подтверждёнными только от наличия отчёта. QR-декодер сохранён исключительно для архивных отчётов 0.3.2.

Описанный ниже `tools/inspect-signals.js` сохранён как прежний инструмент разработчика. Его CLI и область чтения этой страницей не расширены; он не запускается автоматически и не нужен для новой процедуры через iDrive.

Эта процедура **подготовлена, но на автомобиле не выполнялась**. Сначала требуется отдельная команда владельца на доступ к автомобилю и каждое необходимое действие. Здесь нет автоматического SSH, поиска IP, установки, запуска Store, перезапуска MGU или восстановления доступа.

## Что делает инструмент

`tools/inspect-signals.js` запускает только класс `RetroSource` установленного **нашего** приложения и его `kit/signals.js`. Он не загружает `main.js`, `mgu.js`, SDK entry point или renderer, не рисует слой, не открывает техническую страницу и не меняет пользовательскую конфигурацию. Он подписывается на разрешённые источники, выполняет их штатные getters и собирает ограниченный JSON-отчёт. Это SOME/IP чтение, не UDS, OBD, TASU, запуск диагностической сессии, изменение кодировок или запись в блоки.

Используется тот же `source/manifest.json` и тот же каталог `oap_<UID>/someipInterfaces/`, который Store/MainApp сгенерировал для приложения. Путь вычисляется самим `kit/signals.js` относительно его установленного положения. Поэтому произвольный каталог исходников на Mac не заменяет установленное приложение. Инструмент проверяет `source/package.json.name === "manuk_retro_cluster"`, отказывается от `mguBenchOnly:true` и от запуска без настоящего native SOME/IP. Тестовый SDK не даёт «реального» отчёта.

Реальный нативный SOME/IP модуль в коде Store загружается по умолчанию из `/usr/lib/someip.node` (`upstream/mgu-store/deploy/unit/mgu-deploy.js::HMI_READER/mainappHmi`, строки2320–2348). Это основание для параметра `--native-dir /usr/lib`, **не доказательство пути и совместимости установленной версии**. Инструмент сам ничего не ищет и не устанавливает. Если модуль не загружается, проверка заканчивается отказом; не копировать SDK/native файлы в Git и не менять системный Node.

## Подготовка

1. Выполнить проверки версий, штатных предупреждений, конкурирующей темы и ручного выключения из `FIRST_CAR_TEST.md`. Машина стоит, P, стояночный тормоз включён; двигатель включать только в подходящем проветриваемом месте по отдельному решению владельца.
2. Для проверки данных оставить нашу отрисовку выключенной. По возможности завершить обычный экземпляр нашего приложения его штатным способом, чтобы инспектор был единственным читателем нашего источника. Не останавливать BMW-процессы, Store или общий renderer.
3. Установленная версия должна содержать `retro_source.js::diagnostics()`, `config.js` и `kit/signals.js`. Сверить собственный id в `source/package.json`; не угадывать UID, IP и путь приложения по прошлой сессии.
4. Использовать фактический Node целевого runtime. Текущий проект рассчитан на Node8; локальный стенд на Mac не подтверждает исполнение нативного SOME/IP. Если модуль отсутствует/несовместим, остановиться и записать отказ.
5. Заранее выбрать существующий каталог для отчёта. Имя должно быть новым: инструмент не перезаписывает файл. Файл создаётся с правами 0600. Сначала проверить обычное завершение 30 с; увеличение интервала ограничено 120 с.

## Команда, подготовленная для отдельного согласованного запуска

На **самой MGU**, с реальными подтверждёнными путями вместо обозначенных каталогов:

```sh
node /путь/к/исходникам/tools/inspect-signals.js \
  --runtime /реальный/каталог/oap_UID/source/javascript \
  --seconds 30 \
  --output /tmp/retro-signals-first.json \
  --native-dir /usr/lib
```

Все флаги действительно реализованы. `--runtime` и `--output` требуют абсолютных путей. `--native-dir` можно опустить, если native `someip` уже разрешается в том же окружении, что у приложения. Скрипт не должен запускаться на Mac «вместо» чтения автомобиля. Его перенос на автомобиль и команда доступа с Mac являются отдельными согласуемыми действиями; этот документ их не выполняет.

Необязательный параметр **`--tank-litres <подтверждённый_объём>`** принимает число литров в диапазоне схемы конфигурации 1–200. Это границы допустимого ввода, **не объём бака этой BMW**. Указывать параметр можно только с отдельно подтверждённым объёмом; в инструкции намеренно нет примерного числа. Он действует только внутри данного отчёта и не меняет пользовательские настройки. Инспектор не читает всю установленную конфигурацию автоматически. Без параметра он использует `tankLitres:null` из car defaults, что явно отмечается в причине недоступного процента. Поэтому такой отчёт не утверждает, что в пользовательском JSON объём тоже не задан.

По истечении времени инспектор останавливает свои подписки и выходит. Ctrl+C сохраняет имеющиеся данные с `reason: "interrupted"`. Родительский процесс ограничивает время зависшего native вызова; при необходимости завершает только созданный им дочерний процесс инспектора. BMW/Store/MainApp/cluster-render не затрагиваются. Отсутствующий отчёт или отказ native — результат «проверка не состоялась», а не нулевые показания.

## Что есть в отчёте

- До 121 снимка, не чаще примерно 1 с, не более 256 KiB. При достижении лимита сохраняются первый и последние снимки, промежуточные удаляются; счётчик `droppedSamples` явно показывает неполноту истории. Последняя доступность источника остаётся видна.
- `providers`: имя интерфейса, `available`, поколение `epoch`. Это отдельно от пригодности данных.
- `readings`: разрешённые показатели и поля `value`, `unit`, `source`, `quality`, `receivedAt`, `raw`, `candidate`, `candidateUnit`, `inputUnit`, `interval`, `formula`, `reason`, `confirmation`.
- `tankCapacity`: отдельно переданное число или null, `supplied`, происхождение и `confirmation:not-verified-by-probe`. Сам инструмент не подтверждает введённую характеристику автомобиля.
- `fuelL` показывает полученные от Kombi литры. `fuelPct` — только диагностический расчёт `100 × fuelL / tankLitres` из актуальных достоверных литров и явно указанной допустимой ёмкости; это не новый сигнал процентов. Причины отличают отсутствие/устаревание/недопустимость литров от отсутствия подтверждённой ёмкости. Если литров больше заданной ёмкости, процент недоступен, причина требует проверки источника или ёмкости; число не обрезается молча до 100. Эта дополнительная metadata не меняет отображение приборки.
- `oil` и `coolant` содержат каждый свой raw, единицу, timestamp и качество. Например, отсутствующий член или raw 255 у масла не подменяется прежней температурой, даже если ОЖ в том же сообщении пригодна. Доступность CDS сама по себе не означает пригодность обоих членов.
- Raw DSC содержит только `qualifierFunctionFDR/ASC/ABS`. Неизвестное raw значение не становится ON/OFF.
- Не пишутся произвольные структуры, VIN-поля, ключи, пароли, полный каталог автомобиля или параметры чужих приложений. Перед передачей отчёт всё равно просмотреть; он содержит историю показаний, время и, при наличии, одометр. Ненужный одометр можно удалить из передаваемой копии.
- `quality: valid` означает, что наш нормализатор принял тип, единицы и срок актуальности. Это **не подтверждение G30**. `confirmation: not-verified-on-this-car` намеренно не меняется автоматически после получения правдоподобного числа.

Подписки не сохраняют значения как текущие между запусками. При потере provider или неактивном VehicleCondition очистка выполняется исходным классом. Периодические чтения блокированы, пока состояние автомобиля не7/10; начальные getters выполняются стандартным `watch()` при появлении provider. Факт, что сигнал событийный и не меняется 30 с, сам по себе не означает устаревание.

## Таблица сверки

| Источник | Что безопасно сопоставить на месте | Достаточное заключение |
|---|---|---|
| FES | Показанный штатный режим и raw FES; при отдельно разрешённом переключении только обычными кнопками автомобиля — новое имя/код | Отдельно подтвердить каждый реально наблюдённый вариант. Не объявлять другие варианты проверенными. |
| Селектор/передача | Штатное P и соответствующее поле. Номер передачи может быть недоступен | Не включать D/R и не двигаться ради заполнения таблицы. P/R/N и отсутствие номера полноценно тестируются на стенде; автомобильную часть расширять позже отдельно. |
| MDrive программа | Пришёл ли вообще provider/поле; raw и штатная подпись | Если поля нет — программа остаётся недоступной. Положение D не доказывает программу D. |
| ENGINE | Отдельный источник не найден | Наблюдение FES и работающего двигателя не подтверждает профиль двигателя. Оставить прочерк. |
| DSC | Существующая штатная индикация и 3 raw qualifiers | Одно совпадение raw 0 с обычным состоянием недостаточно для таблицы. Не отключать DSC/ABS, не вызывать вмешательство или неисправность ради теста. |
| RPM/скорость/температуры |0км/ч; штатные RPM; доступные проверенные температуры | Записать единицы, значения и availability. Не подгонять коэффициенты под одно число. |
| TPMS | Все 4 давления/температуры со штатного экрана, единицы Vehicle | Нужны raw каждого колеса + фактическая единица. Нет unit signal — не угадывать по диапазону. |
| Наддув | Доступность raw и известный смысл штатной шкалы | Стояночные0/одна точка не доказывают масштаб×0.01 и относительное давление. Пока оставлять unverified. |
| БК1/БК2 и поездка | Штатный экран BC, единицы, интервал после какого сброса | Сверить масштаб в нескольких наблюдениях. Не нажимать Reset ради проверки; не называть BC текущей поездкой без основания. |
| Запас хода/топливо/одометр/наружная температура | Соответствующие штатные показания | Подтвердить поле, масштаб и недопустимые значения; не подставлять объём бака по догадке. |

`ResetLogic.currentConsumption/averageConsumption`, диагностический расход DME и впуск описаны в `DATA_SOURCES.md`, но в текущий пассивный inspector не добавлены. Отсутствие этих данных в отчёте не является проверкой недоступности на машине. Следующий этап — отдельно проверить реальные сгенерированные определения, выбрать конкретные члены и минимальное расширение read-only manifest; не выгружать полный приватный каталог и не подменять это UDS-опросом.

## Сон и завершение

Синее холодное ограничение отдельно исследовано в [COLD_RPM_SIGNAL.md](COLD_RPM_SIGNAL.md). Текущий инспектор выводит внутреннее `coldRpmLimit` как `unavailable`; он не подписывается на предположительные поля и не доказывает их отсутствие на G30. Сначала можно без подключения к машине проверить уже имеющийся локальный каталог утилитой `tools/find-rpm-limit.js`. Найденное имя — только кандидат, а не разрешение подключать его к приборке. Процедура последующего подтверждения указана в том же документе.

Сначала закончить короткую сессию и убедиться, что процесс инспектора завершился. Не держать его запущенным во время ожидания сна, не оставлять опрос на ночь. При следующем отдельном ручном запуске после обычного пробуждения старые показания не должны появляться как свежие. Искусственные разрывы renderer и источников выполняются только в локальном стенде.

Передавать только необходимую копию отчёта после просмотра. Для обычных текстовых логов уже есть `tools/anonymize-log.py`; параметры его запуска указаны в `FIRST_CAR_TEST.md`. Наличие отчёта не разрешает дорожное испытание: сначала проверить реальную видимость скорости, передач, штатных предупреждений и возврат стандартной приборки.
