# Локальный стенд Retro Cluster

Это адаптация `bimmer-lab/apps/bench` на SHA `aaa43e49500ccb4cd6b07537644ac072db49eb99`.
Оригинальный WebGL compositor выполняет те же GLSL и рисует RGBA-слои приложения. Отдельной HTML/CSS реализации приборки нет.

Из корня проекта:

```sh
npm run bench
```

Открыть <http://127.0.0.1:8078>. HTTP слушает только `127.0.0.1`; renderer — временный Unix-сокет. Все данные этой страницы — **имитация**. Изменение исходников приложения, `shared/` и `kit/` автоматически пересобирает и перезапускает только локальный процесс. Остановка: Ctrl+C.

Команда `npm run bench` выбирает `BENCH_FIXTURE=profiles`: при запуске подаются фиксированные искусственные значения COMFORT, 88 км/ч, передача 4, программа D и DSC ON из `profiles-fixture.json`. Часы в рабочих профилях скрыты; в архивном эталонном режиме они идут в текущем времени Asia/Yerevan, если отдельно не задан `BENCH_CLOCK`. Пользовательская конфигурация не сбрасывается. Прямой запуск `node bench/server.js …` без `BENCH_FIXTURE` сохраняет исходный `fixture.json` для эталонного сравнения; переменная `profiles` применяется только к нашему приложению, не к `cluster_themes`.

Внешний интерфейс стенда переведён на русский: кнопки, подписи и единицы ползунков, состояние соединения, таблица слоёв и подсказки. Сырые сообщения технического журнала сохраняются на языке источника для диагностики. Русский интерфейс проверен в Chrome без ошибок JavaScript; снимки — `artifacts/bench_russian_ui.png` и `artifacts/retro_russian.png`.

- Ручные ползунки: скорость (км/ч), RPM, передача, масло/охлаждающая жидкость/впуск (°C), наддув (bar), топливо и прочие значения.
- Кнопки COMFORT / SPORT / ECO и точный список вариантов подают искусственный **сигнал FES**. Они не меняют скорость, передачу, программу коробки или DSC. «Только оформление» принудительно выбирает профиль лишь в стенде, сохраняя точное исходное состояние FES.
- Профиль двигателя, работа двигателя, селектор, фактическая передача, программа коробки и DSC задаются независимо. Данные двигателя остаются в стенде/диагностике; строка двигателя на холсте рабочих профилей скрыта. Отметка рядом с каждым числовым показателем позволяет сделать недоступным только это значение, в том числе один датчик колеса. Мощность рассчитывает реальный код приложения из заданных RPM и момента.
- «Значения для трёх профилей» загружает `profiles-fixture.json`: одинаковые 88 км/ч, 3200 RPM, передача 4, программа D и DSC ON для всех профилей. Это явные искусственные значения, включая пока неподтверждённые автомобильные источники. Старый `fixture.json` и кнопка «Фиксированные значения» сохранены для оригинального эталона.
- «Нет данных»: провайдеры становятся unavailable, события перестают поступать. С включённой галочкой «Проверять освобождение слоёв как на автомобиле» потеря критичных данных освобождает изображение. Без галочки пустые поля можно осмотреть. Автомобильная версия всегда применяет свою защиту.
- «Сон» / «Пробуждение» меняют искусственный VehicleCondition; кнопки renderer обрывают и восстанавливают только локальный транспорт. Отдельные источники отключаются в раскрывающемся блоке; их значения не сохраняются как текущие после сна или потери связи.
- Акцент каждого профиля сохраняется через тот же валидатор и атомарное хранилище приложения и меняет только название режима. Скорость, боковые шкалы и подписи сохраняют светлую основу Adaptive RGB190/198/204 (`#BEC6CC`); Adaptive/unknown светлые и в акцентных полях. Во всех профилях слева находятся вертикальные шкалы текущего расхода, запаса хода и топлива (центры x200/345/490); справа — масло, охлаждающая жидкость и наддув (x1530/1675/1820). Топливо справа не дублируется, средний расход отменён. Шесть вертикальных шкал состоят из15 сегментов каждая; верхняя во всех профилях, включая Eco и нейтральный, показывает RPM в40 равных ячейках по200 об/мин на линейной оси0–8000, с подписями0–8 ×1000. Расход находится только на отдельной левой шкале; номер передачи и скорость используют исходный атлас190px и совместно центрированы; режим/DSC сохраняет свой прежний центр. Сигналы симуляции и принудительный профиль в автомобильную конфигурацию не записываются.
- «Выключить отрисовку» и «Включить отрисовку»: конфигурационный путь приложения, без перезапуска сервиса renderer.
- «Чистый экран»: только canvas 1920×720. «Снимок 1920×720» скачивает canvas, отключив наружные наложения стенда.
- Маска видимости оригинального стенда измерена на **другом автомобиле X3**, выключена по умолчанию и не доказывает видимость предупреждений на G30.
- Ёмкость 65 л в bench — синтетический параметр оригинального эталона; автомобильный профиль не получает его автоматически.

В рабочем представлении перед скоростью показан фактический номер передачи1–8. Передача — x663,y387,w155,h195; скорость — x891,y387,w466,h195, обе используют исходный `d7_gear`190px и светлую основу. Их область x663–1357 имеет центр x1010. Подпись КПП — x650,y605,w181,h37, `ru_unit`34px, центр x740,5; единицы скорости — x1064,y605,w120,h37, центр x1124. Заданный видимый промежуток от передачи до скорости111px, втрое больше межцифрового зазора37px. Режим/DSC не перемещается: x620,y332,w780,h31, `ru_status`28px, независимый центр x1010. Часы и строка двигателя скрыты; архивная Retro сохраняет исходный экран. Переключение профилей не переставляет элементы.

Для DTC строка показывает `SPORT+ / TRACTION`, без префикса DSC; ON/OFF сохраняют DSC. Название режима имеет акцент, разделитель и DSC ON/неизвестное состояние светлые. Только OFF/TRACTION/вмешательство/неисправность в строке состояния становятся жёлтыми. Строка остаётся одним центрированным виджетом с отдельными цветными масками. Режим — фактический FES, а не прочитанный отдельный профиль двигателя. Значения передачи, селектора, программы и двигателя задаются независимо. Крупный номер допускает целые1–8; P/N/R селектора имеют приоритет и повторяются крупно и в подписи КПП. Неизвестные и недопустимые номера дают `-`. Подпись КПП: P/R/N селектора; подтверждённые S/M→S/M; программа D или селектор D→D, иначе `-`. D из селектора обозначает положение, не подтверждённую программу. Контроль потери критичных источников сохраняется. Производный `d7_drive` и генераторы букв сохранены как неиспользуемый ресурс разработки; они не подменяют рабочий цифровой атлас.

Цветовые зоны тахометра одинаковы во всех профилях: участок 0–<6000 об/мин — светлый `#BEC6CC`, 6000–<7000 — жёлтый `#FFE040`, 7000–8000 — красный `#FF3B30`. Подписи 0–5 светлые, 6 жёлтая, 7 и 8 красные. Это фиксированные визуальные зоны, независимые от `redline`, `shiftBefore` и `coldGuard`; сами настройки сохранены. При достоверном RPM от7000 вся шкала из40 ячеек мигает красным `#FF3B30`: яркая фаза и тусклая красная фаза с alpha0,18 сменяются каждые250мс (полный цикл500мс, 2Гц). Ниже7000 действуют обычные белая/жёлтая/красная зоны и заполнение полными ячейками по200. Исходное RPM и рассчитанное по нему заполнение не подменяются максимальным значением ради вспышки. Используется существующий tick, без дополнительных таймеров. Недоступное RPM отменяет мигание; прежняя политика освобождения отображения при потере критичных данных сохраняется. Архивная исходная Retro и настройки redline/shiftBefore/coldGuard не изменены;7000 — фиксированный визуальный порог, не подтверждённый технический предел двигателя.

Для проверки расчёта заполнения верхней шкалы задавайте RPM199/200/400/5999/6000/6999/7000/7999/8000: заполнение соответственно0/1/2/29/30/34/35/39/40 ячеек. Начиная с7000 на холсте мигают все40 красных ячеек, при этом перечисленные расчётные значения сохраняются; недоступное RPM отменяет вспышку. Все40 слотов равны43px при общей ширине1720px: видимое тело40px, зазор3px, скругление2px. Подписи0–8 равномерные; цветовые зоны фиксированы на6000 и7000 об/мин, независимо от redline/shift cue. В renderer передаётся `floor(clamp(rpm, 0, 8000)/200)/40`. Используется свежее нормализованное значение; остальные shared-сглаживания сохранены. Выше8000 заполнение ограничено40 ячейками, недоступное RPM даёт пустую шкалу и прежнюю защиту критичных источников. Настройки `redline`, `shiftBefore`, `coldGuard` и автомобильные сигналы не меняются.

Схема конфигурации 5 переносит старый предел Eco в `profiles.gaugeMax.consumption`; новые максимумы `range` и `fuelFlow` задают только заполнение шкал. Базовые единицы — л/100 км, км и л/ч, независимо от единиц показанного числа. Наддув сохраняет исходную шкалу 0–1,6 bar без нового параметра конфигурации, число использует `d7_sm` в поле 130×47px. Стендовые 0,8 bar — имитация: автомобильный FES-источник имеет неподтверждённый масштаб `q:true`, поэтому в car его значение остаётся `null` и отображается `--`. Нормализация не подменяет недоступные показания и не ограничивает сами значения. Полное описание — `docs/CONFIGURATION.md`.

Состояние стенда: `bench/.data/manuk_retro_cluster/manuk_retro_cluster.json`. Оно отдельно от поставляемого кода и сохраняется при пересборке. Каждый процесс стенда получает собственный каталог `bench/.build/instances/<порт>-<PID>/`: внутри находятся отдельные `sdk-stub/` и приложение. Параллельные стенды больше не удаляют или перезаписывают сборку друг друга. `build-app.py` получает этот каталог явно и вызывает режим **stage only**, который не создаёт устанавливаемых `.mgu`/архивов. В stage дополнительно устанавливается `retroProfile=bench`. На Mac не загружается BMW SDK.

Повторные запросы перезапуска объединяются, пока предыдущий процесс завершает работу; два экземпляра приложения в одном стенде не запускаются. При ошибке сборки панель сообщает именно о локальной сборке и очищает устаревшие значения. Автоматического цикла повторных запусков нет: нужно исправить исходники либо явно повторить запуск. Проверка изоляции, параллельных пересборок и ошибки в временной копии исходников: `node bench/verify-concurrency.js`. Она использует собственные случайные loopback-порты и не меняет открытый рабочий стенд.

## Снимки и анимация

При установленном Google Chrome:

```sh
npm --prefix bench ci
npm run capture
node tools/capture-animation.js
```

Для трёх новых профилей запустите стенд с фиксированным временем для воспроизводимости (часы на холсте скрыты; предыдущий процесс на этом порту сначала остановить Ctrl+C):

```sh
BENCH_CLOCK=14:36 npm run bench
```

В другом терминале:

```sh
node bench/verify-profiles.js
node bench/verify-profile-ui.js
node tools/capture-profiles.js
node bench/verify-profile-media.js
node bench/verify-rpm-scale.js
```

Команда съёмки создаёт `artifacts/comfort.png`, `sport.png`, `eco.png`, `adaptive.png` и примерно 7 секунд `profile-switching.webm`, только canvas 1920×720. Основные показания и время одинаковы, данные берутся из отдельного `profiles-fixture.json`. Отчёты — `profiles-verification.json`, `profiles-ui-verification.json`, `profiles-captures.json`; внешний интерфейс — `profiles_bench_ui.png`. Интеграционный тест сравнивает ссылки и координаты слоёв до и после смены режима, проверяет независимые состояния, недоступное колесо, сон, потерю критичного источника, renderer и сохранение настроек. `verify-profile-media.js` и актуальные отчёты относятся к текущей компоновке; результаты прежних снимков `transmission_*.png` и `selector_*.png` не подтверждают новую компоновку номера1–8 с отдельной подписью КПП. Результаты выполненных проверок фиксируются в `docs/PROFILES_VERIFICATION.md`. Эти команды меняют только локальный стенд.

Не переключайте режим вручную во время съёмки: инструмент проверяет точный профиль и основные показания до и после каждого кадра и откажется принять несогласованный снимок. Для отдельного процесса, не затрагивающего открытую рабочую страницу:

```sh

```

В другом терминале последовательно используйте `BENCH_PORT=8090 node bench/verify-profiles.js`, `BENCH_PORT=8090 node bench/verify-profile-ui.js` и `BENCH_PORT=8090 node tools/capture-profiles.js`. У этого процесса отдельные настройки, сигналы, сборка и временный сокет; рабочий стенд на 8078 остаётся доступным. Проверки и съёмка ждут завершения реального плана HUD: число слоёв и память должны точно соответствовать ему и укладываться в лимиты renderer. Число слоёв не задано устаревшей константой.

Текущий снимок: `artifacts/retro_current.png` (он не перезаписывает результат эталонного сравнения). Запись: `artifacts/retro_animation.webm` (canvas-only 1920×720; MediaRecorder браузера, ffmpeg не требуется). `CHROME_BIN` может указывать другой Chrome/Chromium. Для точного сравнения фиксируется `BENCH_CLOCK=14:36`. В эталоне стоят исходные US/12h единицы, nightDim off и Retro; данные постоянные, автодемонстрация отключена. Впуск отсутствует, потому что диагностический транспорт не имитируется.

## Локальный контроль транспорта

```sh
curl -s http://127.0.0.1:8078/snapshot
curl -X POST -H 'Content-Type: application/json' -d '{"online":false}' http://127.0.0.1:8078/renderer
curl -X POST -H 'Content-Type: application/json' -d '{"online":true}' http://127.0.0.1:8078/renderer
```

Эти адреса относятся только к Mac. `/renderer` закрывает соединения фальшивого renderer; приложение должно переподключиться. По умолчанию включены лимиты 8 слоёв на соединение, 32 суммарно и 16 MiB пиксельной памяти. `/snapshot` содержит состояние, слои и локальные сообщения для проверок.

`BENCH_NODE=/absolute/path/to/node` выбирает изолированный runtime приложения. На этом arm64 Mac официальный Node 8.16.2 darwin-x64 не запускается (Bad CPU type, Rosetta отсутствует), поэтому фактический стенд проверен на Node 24.21.0. Файл Node 8 в `.cache/` не выбирается автоматически. Сам стенд может работать на современном Node. Версия фактически запущенного runtime печатается в журнале. Стенд не проверяет SOME/IP на машине, GPU/композитор приборки, установку, видимость предупреждений и сон автомобиля.

Автоматические проверки живого стенда: `node bench/verify.js` и `node bench/verify-ui.js` (последний также проверяет уже записанный `retro_animation.webm`). Они управляют только локальным стендом и после проверки восстанавливают фиксированные сигналы и включённую отрисовку.

Рабочий тахометр использует производный `retro_tachometer.js` на основе исходного MIT `SHIFTBAR`; hook `_effectShader(w)` в `shared/hud.js` сохраняет оригинальный шейдер для архивной Retro. Настройки акцентов меняют только название режима; геометрия, общая светлая основа и фиксированные цвета тахометра сохраняются.

`verify-rpm-scale.js` предназначен для проверки геометрии и границ заполнения текущей шкалы, фиксированных цветовых зон и подписей0–8 на изолированном стенде. Отчёт — `artifacts/rpm-scale-verification.json`. Прежний результат с28 блоками переменной ширины относится к предыдущей версии и не подтверждает текущие40×200; актуальные результаты фиксируются отдельно в PROFILES_VERIFICATION.md. Скрипт использует `BENCH_PORT`; не направляйте его на рабочий8078 с введёнными вручную значениями.

## Отменённый этап центральных виджетов

Центральные виджеты «Шины», «Музыка», «Навигация» и «Автомобиль» отменены пользователем. Выбор, кнопки листания, endpoint `/widget`, его IPC и телеметрия удалены. Рабочая приборка сохраняет скорость и передачу в центре. Остальные контролы источников и профилей стенда остаются доступны.

Файлы `artifacts/widget_*.png`, `widgets-switching.webm`, `widgets-verification.json` и журналы этого этапа сохранены как история. Они не описывают текущую функциональность и не подтверждают работу музыки, навигации или кнопки BC на автомобиле. Сценарий `bench/verify-widgets.js` удалён вместе с отменённой функцией.

## Предпросмотр настоящих настроек RHMI

После `npm run bench` откройте `http://127.0.0.1:8078/idrive` или ссылку «Предпросмотр настроек iDrive» на главной странице. Это адаптер вызовов настоящего `main.js`/`settings_ui.js`: структура берётся из собранного `rhmiData/uiDescription/uiDescription.json`, начальные строки — из StringId пакета, текущие подписи, состояния checkbox и колонки — из вызовов `ui.text`, `ui.cells`, `ui.checked` и других методов заглушки. Значок загружается из реально собранного ресурса приложения. Подписи настроек не дублируются в HTML.

`GET /rhmi` возвращает состояние этого локального RHMI, а `POST /rhmi-action` принимает `{"component":"SET_ENABLED","row":0}`. Компонент и строка проверяются по реальному активному состоянию, видимости и доступности; действие передаётся зарегистрированному обработчику приложения. Неизвестные, скрытые и неинтерактивные компоненты отклоняются. Экран языка и экран единиц открываются только реальными обработчиками их кнопок. Предпросмотр воспроизводит содержимое и действия приложения, но не доказывает внешний вид и управление на BMW.

«Включать при запуске двигателя» управляет отрисовкой внутри уже запущенного процесса: нужен подтверждённый сигнал двигателя. Краткий stop/start в одной эпохе не гасит приборку; после сна ожидание запуска начинается заново. Эта настройка не включает автозапуск MGU Store: пакет остаётся с `mguAppStartType: manually`.

Изолированная проверка, не затрагивающая ручные значения на 8078:

```sh
BENCH_FIXTURE=profiles BENCH_PORT=8090 BENCH_CLOCK=14:36 BENCH_DATA_DIR="$PWD/bench/.data/idrive-settings-check" node bench/server.js manuk_retro_cluster
```

В другом терминале выполните `BENCH_PORT=8090 node bench/verify-idrive.js`. Проверка управляет настоящими RHMI-компонентами, сохраняет RU/EN снимки и единицы в `artifacts/idrive_*.png`, а результаты — в `artifacts/idrive-verification.json`. Проверяются отключение слоёв, сохранение конфигурации, перезапуск без первого HUD, цикл сна двигателя, независимые единицы и цифры на реальном canvas по исходным атласам. Сценарий отказывается работать на пользовательском порту 8078.
